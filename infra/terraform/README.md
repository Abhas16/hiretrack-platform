# Terraform: HireTrack on AWS

```
infra/terraform/
├── bootstrap/        S3 bucket for remote state (local state, run once per account)
└── envs/dev/         everything else, state in that bucket
    ├── network.tf        VPC: public / private / database subnets over 2 AZs, 1 NAT gateway
    ├── eks.tf            EKS 1.35, access entries, VPC CNI (+NetworkPolicy), Pod Identity agent,
    │                     Graviton spot node group (AL2023 arm64)
    ├── rds.tf            PostgreSQL 16, private, TLS forced, password never in state (password_wo)
    ├── sqs.tf            jobs queue + DLQ (maxReceiveCount 5, SSE)
    ├── ecr.tf            6 repos, immutable tags, scan on push, lifecycle policy
    ├── secrets.tf        SSM SecureStrings for the app (value_wo, generated by ephemeral resources)
    ├── pod-identity.tf   one IAM role per workload, bound to (namespace, service account)
    ├── github-oidc.tf    role GitHub Actions assumes (OIDC, main branch only) to push to ECR
    └── outputs.tf        what Helm and CI need
```

## Design choices (the "why" for interviews)

- **Pod Identity, not IRSA, not keys.** One IAM role per workload, associated with exactly one
  `namespace/serviceaccount`. The scout can only send to the queue, the scorer only receive and
  delete. api, web, reminder-worker and triage-bot have no AWS permissions at all.
- **Secrets never touch the state file.** `ephemeral "random_password"` + write-only arguments
  (`password_wo`, `value_wo`): Terraform sends the value to RDS/SSM and forgets it.
  `secrets_version` bumps rotate them. External Secrets copies SSM into Kubernetes.
- **No account IDs in code.** The state bucket name is passed at `init`, ARNs are built from
  `aws_caller_identity`, the LB controller finds its VPC by tag.
- **Cheap dev, prod-shaped.** Single NAT gateway, single-AZ RDS, spot Graviton nodes. Each
  of them is a one-line change for prod (`one_nat_gateway_per_az`, `multi_az`, `ON_DEMAND`).
- **No Kubernetes objects in Terraform.** Terraform stops at AWS. Argo CD (installed by
  `scripts/bootstrap-cluster.sh`) owns everything inside the cluster, from Git.

## First deploy

```bash
# 0. AWS credentials for an admin user/role in the target account (aws sts get-caller-identity)

# 1. state bucket (once per account)
terraform -chdir=infra/terraform/bootstrap init
terraform -chdir=infra/terraform/bootstrap apply

# 2. the platform (~20 min, EKS is the slow part)
terraform -chdir=infra/terraform/envs/dev init \
  -backend-config="bucket=$(terraform -chdir=infra/terraform/bootstrap output -raw state_bucket)"
terraform -chdir=infra/terraform/envs/dev plan -out=dev.tfplan
terraform -chdir=infra/terraform/envs/dev apply dev.tfplan

# 3. kubeconfig, values-dev.yaml, Argo CD, root app
scripts/bootstrap-cluster.sh
#    then: commit + push values-dev.yaml, set the GitHub variable AWS_ROLE_ARN, run "release"
```

## Cost (ap-south-1, on-demand prices, approximate)

| Item | ~USD / day |
|---|---|
| EKS control plane | 2.40 |
| NAT gateway (+ a little data) | 1.40 |
| 3 × t4g.large spot | 1.80 |
| RDS db.t4g.micro + 20 GB | 0.60 |
| ALB | 0.60 |
| Public IPv4 addresses, CloudWatch, SQS, ECR | 0.40 |
| **Total** | **≈ 7 / day (≈ $210 / month)** |

Run it for a demo or a screenshot session, then **tear it down**:

```bash
scripts/teardown.sh      # app (ALB) first, then Argo CD, then terraform destroy
```
The state bucket (`bootstrap/`) costs cents; keep it for next time.
